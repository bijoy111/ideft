Reproduce the Results

You can re-run every number on this site from the backup-node-selection package. Trained RL models are included, so you do not need to train anything.

Linux (tested on Ubuntu / WSL2) Python 3.10 ~2 GB disk (mostly PyTorch) No root · no Mininet · no SDN controller

1Get the code and set up

git clone https://github.com/bijoy111/ideft.git
cd iDEFT/backup-node-selection/code

python3 -m venv venv
source venv/bin/activate
pip install -r requirements.txt

All commands on this page run from inside backup-node-selection/code/. You can also grab the package from the Downloads page.

2Quick check that it works

python3 backup_selector.py --mode heuristic --seed 42 --out /tmp/mapping.json
python3 rpc_contention_experiment.py --context-seeds 42 --trials 1 --calls 50 --burst 4 \
    --methods baseline heuristic

You should see the mapping each method picked, then a summary table of latency numbers and a Mann-Whitney comparison. If that runs, your setup is ready. Everything below uses the same code with bigger settings.

⚠ One mistake will quietly spoil your results: the scripts add to results_rpc/*.csv instead of replacing it, and the summary at the end reads the whole file. Delete the CSV before each scenario. Every block below starts with rm for this reason. If you skip it, results from different runs get mixed together.

6Optional: retrain the RL models

Trained models come with the package, so you only need this step if you want to check the training itself, or see the 128-host collapse for yourself. 

python3 rl_backup_selector.py --train --timesteps 50000  --model rl_model.zip
python3 rl_backup_selector.py --train --timesteps 80000  --model rl_model_scaled.zip \
    --n-hosts 16 --n-primaries 10 --n-degraded 2 --scale-seed 0
python3 rl_backup_selector.py --train --timesteps 100000 --model rl_model_scaled32.zip \
    --n-hosts 32 --n-primaries 20 --n-degraded 4 --scale-seed 0

# See the collapse for yourself: PPO's default settings break down at 128 hosts
python3 rl_backup_selector.py --train --check-collapse --timesteps 400000 \
    --model rl_model_scaled128_collapsed.zip \
    --n-hosts 128 --n-primaries 80 --n-degraded 16 --scale-seed 0 \
    --ent-coef 0.0 --net-arch 64 64

# The fix used for the reported 128-host results
python3 rl_backup_selector.py --train --check-collapse --timesteps 1000000 \
    --model rl_model_scaled128_v3.zip \
    --n-hosts 128 --n-primaries 80 --n-degraded 16 --scale-seed 0 \
    --ent-coef 0.02 --net-arch 256 256 --n-steps 4096 --batch-size 256
Tip: always add --check-collapse when you train at a new size. It prints how many different backups the policy uses across 5 seeds, so you catch a bad policy straight away instead of part-way through a full run.

Common problems

  • Running the commands from a script: a cd in one shell command does not carry over to the next one. Use cd path && command on each line, or full paths.
  • SimpleXMLRPCServer only queues 5 waiting connections by default. When many primaries share one backup (concentrated, 80 on one), hitting that limit is part of the result. Do not raise the limit to "fix" it, or you are no longer measuring what DEFT actually ships. The retry-with-backoff in the harness handles it and records the failures as data.
  • The RL policy can collapse at any new size, not just 128 hosts. That is why --check-collapse is there.
  • NameError: name 'json' is not defined means the one-line config.py import fix is missing. It is already applied in this package.
